# Defensive security and privacy model

ReleaseProof intentionally runs selected project install/build/start scripts. A project can execute arbitrary local code; a clean copy and narrowed environment reduce accidental contamination but **do not contain malicious code**. Never market `packages/sandbox` as a security sandbox. A future optional container/restricted mode is P2/P3 research, not a blocker for this milestone; it must have a separate threat model before claims.

## Trust boundaries

**SEC-TRUST-001 · P0:** Desktop asks for explicit first-run trust acknowledgement before executing a chosen project; CLI documents the trust precondition and may require `--yes` only for risky opt-ins, not ordinary local use. User-selected target path is validated/canonicalized and cannot escape selected project through symlinks or `..`. Verification workspace is unique and bounded, with no follow-outside-root symlink behavior. Dependency install and target scripts may use network; app itself has no telemetry. Never run upstream real-world corpus with user credentials.

**SEC-ENV-001 · P0:** Build child env from minimal runtime necessities (PATH/Path, PATHEXT, SystemRoot/WINDIR/COMSPEC on Windows, TEMP/TMP, selected home/cache only when technically necessary) plus explicit project `environment.allowHost` and `environment.provide`. Do not copy entire `process.env`; explicitly deny known host credential families by default (`GITHUB_TOKEN`, `NPM_TOKEN`, AWS/cloud provider keys, SSH auth, CI secrets). If a user explicitly allows a value, register it for redaction before any process starts. For tool bootstrap, isolate registry auth: do not copy `.npmrc`, `.pypirc`, pip credentials or host config by default; allow explicit opt-in with warning and sanitized reporting. `CI=true` may be set deliberately. Report names of provided variables, not values.

**SEC-ENVFILE-001 · P0:** `.env.example` and clearly safe template files may be copied; populated `.env`, `.env.local`, production variants and equivalent secret-bearing files are excluded by default. Opt-in (`includeEnvFiles`) requires disclosure, registered value redaction and warning in report. Generic populated values are not automatically “credential leak”; recognized credential pattern or demonstrated client exposure can block, otherwise warn/review. Do not publish raw `.env` content as evidence. The current dirty scanner change is candidate work, not proven final behavior.

**SEC-REDACT-001 · P0:** Central redactor handles known formats plus exact values explicitly provided/allowed and values from opted-in env files. Apply before CLI progress/stderr, worker events, logs, JSON, HTML, AI handoff, screenshots metadata/filenames and error messages. Truncate bounded output *after* ensuring redaction cannot be evaded by chunk boundaries; test secrets split across stdout chunks. Do not store raw logs in renderer/main persistence or temporary diagnostic files. If safe redaction of a value cannot be guaranteed, omit it and mark evidence redacted. Synthetic marker suite must assert zero appearances in every artifact and UI copy path.

## Process, network, file and HTML boundaries

**SEC-PROC-001 · P0:** Prefer executable + argument arrays for ReleaseProof-owned commands. Project-authored package scripts may invoke shell as their intended behavior, but do not concatenate user path/port/env into shell strings. Validate numeric port/timeouts, quote on Windows via tested runner semantics, bind probes to loopback, prevent auto-crawl to external hosts. Kill only tracked PIDs/process groups. Never use `fuser -k` or port-number-based termination. Bounded timeouts/output/file counts stop resource exhaustion; cleanup residue is visible.

**SEC-REPORT-001 · P0:** Treat project README, command output, HTTP bodies, browser page text and report data as untrusted data. Escape HTML text and attributes; serialize JSON in HTML without `</script>` breakout; no `innerHTML`/remote scripts in Desktop. AI handoff quotes or fences untrusted evidence and states it is evidence, not instructions. Local report links/artifact open operations validate generated paths, and URL handling blocks `javascript:`, traversal and untrusted external navigation. Avoid absolute host paths in shareable output where unnecessary.

**SEC-ELECTRON-001 · P0:** Renderer has `nodeIntegration:false`, `contextIsolation:true`, CSP and sandbox when compatible; no remote content; typed preload allowlist; main validates all IPC parameters and limits message size/frequency. Worker is separate from renderer; project execution cannot use renderer privileges. Persistence contains only recent paths/theme/nonsecret settings. Clipboard receives only sanitized report-derived text. Packaged app uses minimum OS privileges, no auto-update network by default.

## Verification claims

No account or telemetry. ReleaseProof may communicate with registries during installs, test app endpoints, and optionally check for updates only with opt-in. A clean workspace is not a safe place to run hostile code; README, Desktop trust notice and reports must say so. Defensive review covers trust paths, redaction, escaping, process lifecycle and packaging without exploitation. See [19](19_RISKS_AND_LIMITATIONS.md) for honest residual risk.
