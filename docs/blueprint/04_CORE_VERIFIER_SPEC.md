# Core verifier normative specification

This file owns verdict semantics; runtime selection details live in [05](05_PROJECT_DETECTION_AND_RUNTIMES.md), report shape in [11](11_REPORTING_AND_AI_HANDOFF.md). All default durations are configurable and recorded. The current implementation is not assumed to satisfy all requirements.

## Input and state machine

**CORE-INPUT-001 · P0:** Accept an absolute/relative existing project directory, explicit target selection when needed, normalized validated config, optional AbortSignal and progress callback. Reject invalid config/paths as user input errors before side effects. Never silently swallow invalid `.releaseproof.json`. Snapshot target root and source commit if a Git checkout; a dirty tree is disclosed, not ignored. Verification phases are `queued/running/passed/warned/blocked/unknown/skipped/cancelled`; every configured required phase has a terminal reason.

**CORE-CLEAN-001 · P0:** Default verification copies source into a unique temporary clean workspace; excludes `node_modules`, build output, caches, `.git`, previous `.releaseproof`, live `.env*` and other sensitive artifacts, retains lockfiles and `.env.example`. Enforce file/size limits, avoid symlink escape/cycles and report copy failures as incomplete/internal according to cause. `--skip-sandbox` should be renamed or deprecated as `--in-place`/`--no-clean-workspace`; it is development-only, explicit and conspicuously labeled. Neither mode is a security sandbox.

## Dynamic pipeline and failure taxonomy

**CORE-INSTALL-001 · P0:** Frozen/reproducible install when a supported lockfile exists; no lockfile mutation; record command, manager/version, lockfile SHA, exit/timeout and bounded redacted tails. A verified broken dependency graph is `APPLICATION_FAILURE`/block; unavailable registry, incompatible manager/toolchain/platform or policy is `VERIFICATION_UNAVAILABLE`/unknown, only when evidence supports that cause. Do not classify every nonzero exit as environment unavailable.

**CORE-BUILD-001 · P0:** Run production build in the clean workspace, not dev server. No build script may be legitimate for an API; mark not applicable only with a reason and runtime proof elsewhere. Missing required user env/external service is unknown; confirmed compiler/source failure is block. Record dependent phases skipped after build failure.

**CORE-PORT-001 · P0:** Preflight the configured/discovered port. A listener present before launch is foreign evidence: return INCOMPLETE with occupied-port finding; never use its HTTP response and never kill it. When a framework can take an allocated ephemeral port, prefer that with explicit command/env propagation. A post-launch listener is not enough: require owned process/tree alive and correlated HTTP response. If ownership cannot be established, unknown. Cover IPv4/IPv6, races and an app ignoring requested port.

**CORE-RUNTIME-001 · P0:** Detect readiness and then observe a default ≥5-second configurable stability window, repeated HTTP and process liveness. Verified delayed crash or HTTP 5xx from the owned app blocks. A live process whose HTTP request times out without attributable cause is unknown; documented external dependency is unknown. No successful startup/route evidence for a runnable app means INCOMPLETE, even with perfect static checks. A workspace root without selected runnable target is INCOMPLETE and prompts target selection.

**CORE-HTTP-001 · P0:** Separate API endpoint responses from browser documents. A declared API 204/2xx can pass despite empty body. Expected 401/403/404 or redirects can pass **only** when configured or semantically supported by route metadata; unexpected 4xx is contextual warning/unknown, not automatic broken-app proof. 5xx on a configured critical route is block unless evidence attributes it to missing external infrastructure. Health path is configurable; root `/` is not always a valid API health route. Do not POST/alter state by auto-discovery.

**CORE-ROUTES-001 · P1:** Combine explicit `criticalRoutes` with bounded, reliable static/manifest discovery. Each route has path, GET method for automatic probing, kind (`page`/`api`), expected status/range if configured, source and discovery confidence. Dynamic route templates with missing parameters are not probed blindly; authenticated/stateful routes require explicit safe configuration. Report attempted vs skipped routes, cap depth/pages and prevent navigation to external hosts. A failing configured critical route blocks on proven app failure. Do not claim coverage of all routes/business flows.

**CORE-BROWSER-001 · P0:** For browser-capable targets, launch Playwright and observe page errors, critical failed requests and DOM state for default ≥2 seconds after DOMContentLoaded; capture delayed exceptions. Benign console warnings/analytics/favicons do not block without demonstrated app impact. A browser launch failure becomes `HTTP_FALLBACK` (HTTP only) or `UNAVAILABLE`, never `VERIFIED`; a browser app without browser runtime proof is INCOMPLETE absent an independent blocker. API-only target may legitimately be `SKIPPED`/not applicable. Distinguish Playwright infrastructure failure from page navigation/application failure; do not catch both and relabel as fallback. Browser checks must use only local target origin unless explicitly allowed.

**CORE-ENV-001 · P0:** Child environment is a minimal OS/runtime allowlist plus explicit per-project allow/provide values. Do not inherit unrelated host tokens. `includeEnvFiles` is off by default; explicit opt-in is disclosed and values registered for redaction. `.env.example` documents names/default placeholders but does not provide secret values. Missing required user values and unavailable external databases/SaaS yield unknown, not blocker without code-failure proof. See [10](10_SECURITY_PRIVACY.md).

**CORE-CANCEL-001 · P0:** AbortSignal cancellation is cooperative across copy, install, build, startup, browser and report generation. It stops new phases, kills owned children, closes browser, disposes workspace and returns a distinct cancelled result/UI state (not READY/NOT_READY). Timeouts have per-phase bounds and overall bound; cleanup failure is visible. CLI SIGINT exits 130 after cleanup, Desktop Cancel returns to a valid retry state. No Core-level `process.exit` or global one-run signal handler.

## Check status, classification, score, verdict

`pass` = observed success; `warn` = nonblocking concern; `block` = demonstrated application/release failure; `unknown` = required verification could not reach a trustworthy conclusion; `skipped` = intentionally not run (must say why); `not_applicable` = proven outside selected target's capability. Classification is orthogonal: `APPLICATION_FAILURE`, `VERIFICATION_UNAVAILABLE`, `EXTERNAL_DEPENDENCY_UNAVAILABLE`, `RELEASEPROOF_INTERNAL_ERROR`. Internal error never becomes an application blocker.

**CORE-SCORE-001 · P0:** Preserve the current category weights: install 15, build 15, runtime 20, browser 15, API/routes 10, environment 10, documentation 5, security 10. For each category, divide its weight equally among applicable checks; `pass=1`, `warn=0.5`, `block/unknown/skipped=0` credit. A category proven `not_applicable` is excluded from the denominator; an unexecuted **required** category is represented by an explicit unknown/skipped check and stays in the denominator. Score = rounded `100 × sum(weight × credit) / sum(applicable category weights)`; if denominator is zero, score 0. Category status precedence is block > unknown > skipped > warn > pass, with all-N/A reported N/A. Publish separate evidence coverage: completed-with-observation required checks (`pass/warn/block`) divided by all applicable required checks (`pass/warn/block/unknown/skipped`), excluding N/A; 0/0 coverage is 0. A blocker can coexist with a high numeric score only if verdict remains NOT READY and UI never styles the score as readiness. `READY 100` cannot occur without dynamic runnable evidence. Missing required phases must be materialized as unknown/skipped checks before scoring, never omitted to inflate the score.

**CORE-VERDICT-001 · P0:** Truth table, evaluated in order: (1) any demonstrated blocker → `NOT_READY`; (2) else internal error, required unknown/skipped, missing runnable proof, browser capability missing for browser app, or no meaningful checks → `INCOMPLETE`; (3) else `READY`. Intentional `not_applicable` never forces incomplete. Warnings alone may allow READY. Unknown and skipped never equal pass. A cancelled run has no shipping verdict and is not included in readiness metrics. Report stores the exact reasons and capabilities behind decision.

## Cleanup and observability

**CORE-CLEANUP-001 · P0:** `finally` closes browser, terminates owned process tree (grace then force), waits for port/process exit, removes temp workspace with bounded retry, and records any residue path/reason without deleting arbitrary user files. Report generation occurs only after sensitive data redaction; it must not depend on retained temp paths. Tests must inspect actual processes/ports/temp dirs after success, error, timeout, SIGINT, Cancel and Desktop close.
